# Freedom Broker — Conversation Quality Analytics (CQA)

Прототип системы автоматической оценки качества клиентских чатов и звонков, апелляции и пересмотра результатов (разработан для хакатона **Freedom Broker CQA Hackathon**).

---

## 🚀 Быстрый запуск (0 внешних зависимостей)

Серверная часть использует стандартную библиотеку Python 3 (`http.server`, `sqlite3`, `urllib`, `json`) и запускается одной командой без необходимости установки сложных зависимостей.

```bash
python3 server.py
```

После запуска откройте в браузере:
- **Основной интерфейс CQA:** [http://localhost:8080](http://localhost:8080)
- **Предпросмотр HTML-компонента Microsoft Dynamics 365:** [http://localhost:8080/?d365=1](http://localhost:8080/?d365=1)

При первом запуске создаётся локальная база SQLite `data/cqa.db` и загружается базовый чек-лист. Датасеты, база, аудиозаписи и кэш намеренно не входят в публичный репозиторий: они могут содержать персональные данные и записи разговоров. Для работы загрузите разрешённый JSON через интерфейс или настройте URL API организаторов:

```bash
export ORGANIZER_API_URL='https://your-authorized-dataset-endpoint'
python3 server.py
```

Если URL содержит токены доступа, храните его только в переменной окружения и не добавляйте в исходники, Git или публичные логи.

## ✨ Реализованный функционал

### Контур 1 · Настройка и автоматическая оценка
1. **Конструктор чек-листа (`📋 Конструктор чек-листа`)**:
   - Создание, редактирование и удаление критериев, изменение формулировок, секций, весов, типа ответа (`ДА / НЕТ`, `Числовая шкала 0–N` с настройкой ступеней, `Грубая ошибка — без баллов`) и доступности `N/A`.
   - Готовые пресеты в 1 клик для контрольной проверки жюри (замена/добавление критерия с мгновенным пересчётом всех выданных диалогов).
2. **Загрузка данных и адаптер API организаторов (`⬇️ API group_id` / `📂 Загрузить JSON`)**:
   - Прямая загрузка наборов по параметру `group_id` (`DEV` или контрольный `group_id` на 23-м часу хакатона) через серверный адаптер (устраняет ошибки CORS).
   - Поддержка ручной загрузки JSON-файлов с транскриптами.
   - Полная поддержка **RU, KZ и EN** диалогов. Реплики `bot` и `system` маркируются и учитываются как контекст (время эскалации, подтверждение личности, обрыв соединения).
3. **Математика расчёта и перераспределения весов при N/A**:
   - Точная реализация алгоритма со стр. 2 PDF «Чек-лист качества чатов»:
     - Перевод шкальных оценок пропорционально весу критерия: `(выбранная_ступень / макс_ступень) × вес`.
     - Исключение критериев с `N/A` и пропорциональное перераспределение их весов между применимыми критериями так, чтобы максимум всегда составлял **100.00 баллов**.
     - Округление итогового балла до двух знаков после запятой; отдельный учёт флага **«08 Грубые ошибки»** (оскорбления, платные услуги в обход компании, раскрытие данных счёта без идентификации).

### Контур 2 · Работа с результатом, апелляция и пересмотр
4. **Интерактивная карточка диалога, аудиоплеер и распознавание речи CMU PocketSphinx**:
   - Клик по любой реплике-доказательству в обосновании критерия плавно прокручивает и подсвечивает нужную реплику в транскрипте.
   - Для телефонных звонков (`voice call`) встроен HTML5-аудиоплеер с серверным проксированием потока (`/api/audio/<id>`), распаковкой HTML/JSON-обёрток Power Automate и переходом к нужному таймкоду (`offset_seconds`) по клику на доказательство или метку времени.
   - Встроен модуль **CMU PocketSphinx ASR (`asr_pocketsphinx.py`)**: конвертация аудио в `16 kHz 16-bit mono PCM WAV` через `ffmpeg`, акустическая VAD-сегментация (`pocketsphinx.Segmenter`), декодирование (`pocketsphinx.Decoder`), вычисление уровня сигнала (`dBFS`) и автоматическое исправление билингвальных KZ/RU искажений транскрибации (кнопка `🎙️ PocketSphinx ASR` и загрузка `.wav`/`.mp3` файлов в плеере звонка).
5. **Подача апелляции (`⚖️ Оспорить критерий`)**:
   - Пользователь выбирает спорный критерий, добавляет комментарий и сохраняет обращение.
6. **Решение проверяющего (`✅ Решение проверяющего` и вкладка `⚖️ Апелляции и Пересмотр`)**:
   - Проверяющий видит спорную оценку, комментарий оператора и фрагмент диалога, подтверждает исходную оценку или меняет её с указанием причины.
   - Система автоматически пересчитывает итог и сохраняет в карточке всю историю: **Исходная оценка ИИ → Обращение (Апелляция) → Решение проверяющего → Финальный результат**.

## 🧮 Архитектура гибридного решения: 4 взаимосвязанных класса алгоритмов

В архитектуре системы `Freedom-CQA-Hybrid` (`evaluator.py`, `asr_pocketsphinx.py`) задействовано четыре взаимосвязанных класса алгоритмов:

### 1. Детерминированные математические алгоритмы и агрегация
- **Алгоритм динамической перенормировки весов при $N/A$ (Dynamic Weight Rebalancing):** При выпадении любого критерия в статус $N/A$ базовый вес исключается, а веса остальных применимых критериев пропорционально масштабируются к 100 баллам:
  $$W_{\text{active}} = \sum_{j \notin N/A, \, j \neq 8} w_j, \qquad S_{\text{scaled}}^{(i)} = \frac{\text{raw\_score}_i}{\text{max\_raw}_i} \cdot w_i$$
  $$\text{Total Score} = \text{round}\left(\sum_{i \notin N/A} \frac{S_{\text{scaled}}^{(i)}}{W_{\text{active}}} \times 100, \; 2\right)$$
  Алгоритм строго гарантирует сохранение диапазона $[0, 100]$ и округление до двух знаков после запятой.
- **Триггерный алгоритм обработки катастрофических событий (Critical Fail Override):** Логический триггер для критерия `08`: булева маска (`critical_fail_override`), которая не ломает шкалу весов $W_{\text{active}}$, но маркирует статус диалога как критический сбой (`BLOCKED_CRITICAL_FAIL`) и блокирует допуск оператора к прохождению аудита.
- **Временной разностный алгоритм валидации SLA (Time-Delta Verification):** Парсинг временных рядов реплик (`MM:SS` и `ISO 8601`) с вычислением задержки первого ответа оператора:
  $$\Delta t_{\text{first}} = t(\text{first\_operator\_reply}) - t(\text{first\_client\_message})$$
  Если $\Delta t_{\text{first}} > 180\text{ с}$, алгоритмически накладывается верхняя граница на критерий `06` ($\text{Score}_{06} \le 7$ баллов), исключая человеческий или модельный фактор.

### 2. Актуарные алгоритмы и теория вероятностных рисков
- **Оценка квантилей задержек (Empirical Quantiles & Weibull VaR):** Временные интервалы ответов оператора $\Delta t_k$ формируют выборку с выраженным «тяжёлым хвостом». Алгоритм вычисляет показатель Value-at-Risk ($VaR_{0.95}$):
  $$VaR_{0.95} = \inf \{ t \in \mathbb{R} : P(\Delta t > t) \le 0.05 \}, \qquad VaR_{0.95}^{\text{Weibull}} = \lambda \cdot (-\ln 0.05)^{1/k}$$
  Значение определяет порог задержки, который оператор не превышает в 95% случаев внутри конкретного разговора.
- **Модель совокупного риска диалога (Collective Risk Model):** Диалог рассматривается как сумма дискретных событий отклонений от стандартов:
  $$\text{Risk Index} = \sum_{i=1}^{m} w_i \cdot \left(1 - \frac{\text{score}_i}{\text{max\_score}_i}\right)$$
  Это переводит стандартную оценку качества в метрику финансово-операционного риска для супервизора (`LOW` / `MODERATE` / `HIGH` / `CRITICAL`).
- **Байесовская оценка достоверности скоринга (Bayesian Confidence Engine):** Моделирование уверенности системы через параметры Бета-распределения $\text{Beta}(\alpha, \beta)$, где объём подтверждённых индикаторов выступает апостериорным обновлением:
  $$\mathbb{E}[p] = \frac{\alpha}{\alpha + \beta}, \qquad \text{Var}(\text{Beta}(\alpha, \beta)) = \frac{\alpha \beta}{(\alpha + \beta)^2 (\alpha + \beta + 1)}$$
  Если дисперсия превышает пороговое значение ($\text{Var} > \sigma^2_{\text{thresh}}$), система автоматически генерирует флаг **«Рекомендован выборочный аудит супервизором»**.

### 3. Алгоритмы обработки естественного языка и структурированного вывода (NLP / LLM)
- **Алгоритм управляемого декодирования со строгой грамматикой (Constrained JSON Decoding / Structured Outputs):** Вместо генерации произвольного текста языковая модель ограничивается конечным автоматом состояний (на базе Pydantic / JSON Schema `build_constrained_json_schema` и `enforce_constrained_decoding_fsa`). Оценки для шкальных критериев `04` и `06` могут принимать только значения из дискретных множеств:
  $$\text{Score}_{04} \in \{0, 5, 10, 15, 20, \text{"N/A"}\}, \qquad \text{Score}_{06} \in \{0, 4, 7, 10\}$$
  Это математически исключает появление некорректных чисел (например, `8` или `13`).
- **Алгоритм точечной экстракции доказательств (Targeted Evidence Extraction):** Сопоставление семантического вывода с конкретным индексом строки транскрипта (`evidence_line_index`) и точной цитатой (`evidence_quote`), связывающее NLP-вывод с физическим объектом `#turn-{evidence_line_index}` в DOM-дереве браузера и таймкодом аудиоплеера.

### 4. Алгоритмы цифровой обработки акустических сигналов и распознавания речи (DSP / ASR — CMU PocketSphinx)
- **Алгоритм спектрально-энергетической детекции голосовой активности (Acoustic VAD & RMS dBFS Profiling):** Ресемплинг входного аудиопотока к $f_s = 16\,000\text{ Гц}$ (`16-bit mono PCM WAV`) и выделение границ речевых сегментов через `pocketsphinx.Segmenter` с расчётом среднеквадратичной мощности каждого сегмента:
  $$\text{RMS}_{dBFS} = 20 \log_{10}\left(\frac{1}{32768}\sqrt{\frac{1}{N}\sum_{n=1}^{N} x_n^2}\right)$$
- **Алгоритм декодирования Витерби на скрытых марковских моделях (HMM-GMM Viterbi Beam Search Decoding):** Поиск наиболее вероятной последовательности слов $\hat{W}$ по акустическим векторам MFCC-признаков $O = (o_1, \dots, o_T)$ в декодере `pocketsphinx.Decoder`:
  $$\hat{W} = \arg\max_{W} P(O \mid W; \Theta_{\text{HMM}}) \cdot P(W; \Theta_{\text{LM}})^{\alpha_{\text{lw}}}$$
  с вычислением логарифмического акустического правдоподобия (`acoustic_score`), апостериорной вероятности гипотезы и покадрового выравнивания границ слов с шагом $10\text{ мс}$.
- **Алгоритм фонетико-лексической коррекции билингвального переключения кода (Bilingual Code-Switching Phonetic Repair):** Автоматическое устранение фонетических искажений при переключении языка «Казахский ↔ Русский» в телефонных звонках (например, реконструкция приветствия *«Сәлеметсіз бе, Фридом Брокерге қош келдіңіз!»* в звонке `p4-ru-003`).

## 🤖 ИИ-модель и стоимость одной оценки (FAQ)

Система поддерживает два режима работы (переключаются во вкладке `📊 Аналитика и Стоимость ИИ`):
1. **Встроенный гибридный многоязычный движок `Freedom-CQA-Hybrid` (по умолчанию)** — работает локально и мгновенно (0 ₸, без внешних ключей), оценивая все 8 базовых и любые пользовательские критерии на RU / KZ / EN.
2. **Внешний LLM API (`Google Gemini 2.5 Flash` / `OpenAI GPT-4o-mini` / `Ollama`)**:
   - **Модель:** `gemini-2.5-flash` (или `gpt-4o-mini`)
   - **Количество вызовов на 1 оценку диалога:** `1 вызов` (единый структурированный JSON-ответ по всем критериям активного чек-листа с цитированием индексов реплик).
   - **Средний расход токенов на 1 диалог:** `~1 150 входных токенов` + `~420 выходных токенов`.
   - **Примерная стоимость 1 оценки (с учётом всех вызовов):** **`~$0.00042 USD` (≈ `0.21 ₸` за 1 диалог)**, или **`~$0.027 USD` (≈ `13.6 ₸`)** за весь набор из 65 диалогов.

- Отправляет события `postMessage` (`FreedomBroker.CQA.WebResource`) в родительскую форму Dynamics 365 при выборе диалога и пересмотре оценки.
