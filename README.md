# Freedom CQA

**Качество диалога — это не только итоговый балл. Важно понимать, откуда он взялся.**

Freedom CQA помогает разбирать клиентские переписки и звонки: показывает диалог рядом с оценкой, связывает выводы с конкретными репликами и даёт оператору возможность оспорить решение.

Проект создан для Freedom Broker CQA Hackathon. Это прототип для локального запуска и демонстрации; перед использованием с реальными клиентскими данными настройте доступ и правила их хранения.

## Что можно сделать

- **Быстро найти разговор:** искать по ID и тексту, отбирать звонки, язык и диалоги с критическими ошибками.
- **Проверить оценку по репликам:** перейти из критерия к подтверждающей цитате в транскрипте; для звонков — перемотать аудио к нужному времени.
- **Учесть контекст:** реплики клиента, AI-ассистента, оператора и системные события отображаются отдельно. Поддерживаются русский, казахский и английский языки.
- **Настроить критерии:** изменить чек-лист, шкалы, веса и правила N/A; применить его и пересчитать диалоги.
- **Провести пересмотр:** отправить апелляцию, приложить аргументацию и сохранить решение проверяющего с пересчитанным результатом.
- **Подключить модель:** использовать встроенный аналитический движок или настроить Google Gemini, OpenAI-совместимый API либо Ollama.
- **Разобрать звонок:** слушать запись, перейти к таймкоду и, при установленном PocketSphinx, запустить локальное распознавание речи.

## Запуск за минуту

Нужен Python 3. Запустите сервер из корня проекта:

```bash
python3 server.py
```

Откройте **http://localhost:8080**. Чтобы выбрать другой порт:

```bash
PORT=8081 python3 server.py
```

При первом запуске сервер создаст `data/cqa.db` и базовый чек-лист. **Диалоги в публичный репозиторий не включены**, поэтому список будет пуст, пока вы не загрузите разрешённый набор.

### Подключить набор диалогов

Введите `group_id` в интерфейсе. Если набор доступен через API организаторов, задайте адрес API до запуска сервера. Для URL с токеном введите его скрыто, чтобы не сохранять в истории команд:

```bash
read -rsp 'URL API организаторов: ' ORGANIZER_API_URL
printf '\n'
export ORGANIZER_API_URL
python3 server.py
```

Сервер добавляет к адресу параметр `group_id`. Либо загрузите подготовленный JSON через API проекта:

Endpoint загрузки принимает объект с полем `payload`; внутри него может быть массив записей, объект `{"records": [...]}` или ответ с записями в `data.records`. Например:

```bash
curl -X POST http://localhost:8080/api/conversations/upload \
  -H 'Content-Type: application/json' \
  --data-binary '{"group_id":"CUSTOM","payload":{"records":[{"conversation_id":"example-1","transcript":[{"role":"client","text":"Здравствуйте"}]}]}}'
```

Для каждой записи нужны `conversation_id` и `transcript`; остальные поля, например `language`, `channel` и `audio_url`, используются при наличии.

## Как устроена оценка

Для каждого разговора CQA показывает итог, разбивку по критериям, доказательства, индикаторы риска и задержки ответов. Шкальные критерии используют только заданные ступени, а `N/A` исключает неприменимый вес и перенормирует остальные критерии.

Критический критерий учитывается отдельно от обычной суммы баллов: его срабатывание помечает разговор как требующий внимания, а не незаметно растворяется в среднем балле. Проверяющий может подтвердить исходную оценку или изменить ответ; история решения и новый итог сохраняются.

Система сочетает детерминированные правила и арифметику, показатели риска и уверенности, а при настройке — структурированную оценку языковой моделью. Внешняя модель необязательна: встроенный движок работает без API-ключа. Балл и рекомендации — инструмент для проверки, а не замена решения специалиста.

## Модель и аудио

### Внешняя LLM

Провайдера, модель и ключ можно настроить в интерфейсе. Поддерживаются Gemini, OpenAI-совместимые API и Ollama. Можно также передать `GEMINI_API_KEY` через окружение при первом запуске.

Ключи и рабочие данные хранятся локально в SQLite (`data/cqa.db`). Не публикуйте эту базу, не добавляйте ключ в исходный код и не передавайте реальные клиентские данные внешней модели без разрешения. Стоимость внешней оценки зависит от модели, тарифов провайдера и размера диалога.

### PocketSphinx

Распознавание речи — дополнительная функция. Установите PocketSphinx и `ffmpeg`, если хотите запускать локальную ASR-обработку; без них сервер и основные функции оценки остаются доступны. На поддерживаемой системе:

```bash
python3 -m pip install pocketsphinx
```

Модуль ASR нормализует аудио для распознавания, выделяет речевые сегменты и может исправлять известные ошибки русско-казахского переключения языка. Точность распознавания зависит от записи, языка и акустических условий.

## Данные и конфиденциальность

В `.gitignore` исключены `data/`, `dev_dataset.json`, виртуальное окружение и `.env`. В локальной папке данных находятся SQLite-база и кэш аудио; они могут содержать ключи, транскрипты и записи разговоров.

- Используйте только наборы, которые разрешено обрабатывать.
- Храните URL с токеном, API-ключи и клиентские данные вне Git.
- Передайте реальные данные внешнему LLM только при наличии соответствующего разрешения.
- Для производственного использования отдельно настройте аутентификацию, сетевые ограничения, сроки хранения и удаление данных. Локальный демонстрационный сервер сам по себе не является защищённой production-системой.

## Разработка

Бэкенд использует стандартную библиотеку Python; PocketSphinx и `ffmpeg` нужны только для соответствующих сценариев обработки аудио. Интерфейс загружает Tailwind CSS и шрифты из CDN, поэтому для их получения браузеру нужен доступ в интернет.

В проекте нет отдельной команды тестирования. Перед отправкой изменений проверьте синтаксис Python:

```bash
python3 -m py_compile server.py evaluator.py asr_pocketsphinx.py
```
